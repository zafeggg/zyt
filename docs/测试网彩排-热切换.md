# 测试网热切换彩排手册（BSC Testnet，chainId 97）

> 为什么用测试网而不是主网 fork：fork 需要 archive 级 RPC（免费公共端点全部不满足），而测试网有**真实旧合约 + 已建好的池**，同一批脚本可直接跑真交易，比 fork 更接近实战。
>
> 旧栈来源：`zyt-contracts/deployments/bscTestnet-20260924.json`（v9.1，21 亿 ZYT + 21,000 U 已建池，LP 已锁）。

## 1. 部署 + 接线（**不切代币**）

```powershell
node scripts/deploy-hotswap.mjs
```
产出 `deployments/hotswap-<ts>.json`（含 5 个新地址 + 旧地址 + 基线快照 + `switched:false`）。

## 2. 未切换态自检

```powershell
$env:HOTSWAP_FILE="deployments/hotswap-<ts>.json"
node scripts/post-hotswap-check.mjs
```
期望：A 组「零资产移动」全部相等；B 组四点仍指向**旧**合约；C/D 组新参数与接线全绿。

## 3. 账本迁移

```powershell
$env:NEW_MINING="<记录里的 ZYTMining>"
$env:NEW_CONFIG="<记录里的 ZYTConfig>"
$env:BATCH_SIZE="50"

node scripts/migrate.mjs snapshot      # 枚举 + 旧币持仓 + 未领分红 + 直推累计
node scripts/migrate.mjs launchday --execute
node scripts/migrate.mjs push --execute
node scripts/migrate.mjs verify        # 逐户比对
```
> `snapshot` 日志里如出现「严重警告：directDeposit 全为 0」必须停下——否则所有老用户会掉到 2% 档。

## 4. 分红垫付（按实测残值）

```powershell
node scripts/dividend-drain-report.mjs    # 读取未领分红合计（主网实测仅 9.28 万 ZYT）
# 若新池 dividendPoolZyt < 未领合计 → 用 seedDividend 补足
```

## 5. 切换四点（仅切换，不重新部署）

```powershell
node scripts/deploy-hotswap.mjs --switch-only
node scripts/post-hotswap-check.mjs       # 此时 B 组应全部指向新合约
```

## 6. 小额冒烟（切换后）

1. 小额 `deposit`（100U）→ 确认入金分账、算力记账
2. 小额 `buy` → 确认阶段门控与买额
3. 窗口日 `sellZyt` → 确认档位、额度、滑点（当日档位由 08:01 定档决定）
4. `claimDividend` → 确认新池 `dividendPoolZyt` 足够

## 7. 回退演练（对象：测试网）

```powershell
node scripts/rollback.mjs --dry-run       # 先看步骤
node scripts/rollback.mjs                 # 真实回退
node scripts/post-hotswap-check.mjs       # B 组应回到旧合约；A 组储备不变
```

回退后应确认：代币四点回到旧地址、旧 Config `unpause`、旧账本读数与第 3 步前一致。

## 已知差异（测试网 vs 主网）

| 项 | 测试网 | 主网 |
|---|---|---|
| USDT | Mock 代币（可 faucet） | 真实 USDT |
| 池深度 | 与主网不同 | 1,501,847,466 ZYT + 33,943 U |
| 分红池残值 | 可能为 0 | 4,975 万 ZYT / 未领 9.28 万 |
| 滑点定档 | 可用 keeper 手动触发 `dailySnapshot` 观察 | 同 |

彩排通过后，主网当天的动作与第 1→2→3→4→5→6 步完全相同，只是地址与私钥换成生产值。
