# ZYT 主网密钥管理规范（.env 版，2026-09-14 决策）

> 决策：不使用密码加密 keystore。部署/owner 私钥以明文存本地 `.env`，不上传服务器；keeper 签名私钥以明文存服务器 `.env`。
> 适用：ZYT 主网（BSC chainId 56）部署与运维全流程。

## 1. 私钥分布总表

| 私钥 | 存放位置 | 合约权限 | 泄露后果 | 止损手段 |
|---|---|---|---|---|
| 部署/owner | 本地 Windows `zyt-contracts/.env` 的 `PRIVATE_KEY`（**不上服务器**） | 9 合约全部 owner（暂停/参数/白名单/接线/所有权） | 项目级失控，不可逆 | 提前准备新钱包接盘 `transferOwnership` |
| keeper 签名 | 服务器 keeper `.env` 的 `KEEPER_PRIVATE_KEY`（`chmod 600`） | 仅触发 dailySnapshot（合约 require 锁定，无资金权限） | 恶意 totalPower 稀释产出 | `config.setAddress("keeperAddress", 新地址)` 即止损 |

## 2. 本地 .env 三不原则（owner 私钥安全底线）

1. **不进云同步**：`zyt-contracts/` 目录不得位于 OneDrive / 坚果云 / 网盘同步路径下，云盘自动上传是明文私钥最常见泄露路径。
2. **不进 Git**：`.env` 已在 `.gitignore`（执行 `git check-ignore zyt-contracts/.env` 复核）；任何分支/提交历史不得出现私钥。
3. **不留长期副本**：主网部署完成后，将 `PRIVATE_KEY` 值清除或替换回测试私钥；原始私钥纸质抄录 + 断电介质（U盘）保存，与 `.env` 分离。

补充：部署当日保持杀软开启、关闭浏览器剪贴板扩展；deployer 地址提前充好 gas 与 2.1 万 USDT，避免部署中途长时间停留。

## 3. 服务器 .env 规范（keeper 私钥）

```bash
# 权限收紧（一次性）
chmod 600 /path/to/zyt-keeper/.env
chown <keeper运行用户> /path/to/zyt-keeper/.env

# 复核未入库
cd /path/to/zyt-keeper && git check-ignore .env   # 有输出 = 未入库 ✓
```

- keeper 地址无资金权限，泄露后果可控；仍应避免备份到公开/异地明文位置。
- 服务器被入侵的极端场景下，私钥可被读取，止损路径为 owner 调 `setAddress("keeperAddress", 新地址)`。

## 4. 主网部署流程

```bash
# 0. 前置：deployer 充 ≥0.05 BNB（gas）+ 2.1 万 USDT（底池 initialize）
# 1. .env：PRIVATE_KEY 替换为主网 deployer 私钥；确认 MARKET_ADDRESS / TECHNICAL_ADDRESS / KEEPER_ADDRESS
# 2. 部署（交互输入 yes 确认网络与地址；脚本化场景 CONFIRM_MAINNET=1）
npx hardhat run scripts/deploy.js --network bsc
# 3. 验证合约（verify 脚本）
# 4. 部署完成立即：.env 的 PRIVATE_KEY 清除/换回测试私钥；deployer 仅留少量 gas
```

- 部署全程在本地执行，服务器无部署角色，`.env` 私钥不上传。
- confirmMainnet 会打印网络（chainId 56）与 deployer 地址，输错或取消均不会发出交易。

## 5. 应急轮换（怀疑泄露时）

1. owner 私钥疑似泄露：用干净环境立即执行 `transferOwnership(新钱包)` 逐合约轮换（9 合约 + Config 内 keeperAddress 重设），随后作废旧私钥。
2. keeper 私钥疑似泄露：owner 调 `config.setAddress("keeperAddress", 新地址)`，旧地址立即失效。
3. 本地 .env 物理泄露（误传网盘/Git）：按 1 处理；若尚未部署主网，直接弃用该私钥换新。
